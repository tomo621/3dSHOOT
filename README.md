# タクティクス戦闘プロトタイプ(タイトル未定)

Unity製、グリッド上を移動して戦うターン制タクティクスの戦闘ループ・プロトタイプです。

## 概要(現状のスコープ)

- 10x10グリッド上をクリックで移動、射程内の敵をクリックで攻撃(隣接なら近接・離れていれば遠距離を自動で切り替え)
- 敵は1ターンに1体だけ行動する簡易AI。近接タイプはプレイヤーを追跡して隣接攻撃、遠距離タイプ(ステージ2以降に出現)は一定距離を保ちながら攻撃してくる(他の敵・プレイヤー・障害物マスとは重ならないよう移動先を調整)
- グリッド内にはステージ番号から決まる進入不可の障害物マスがあり、プレイヤー・敵どちらの移動判定にも反映される
- 敵を倒すと経験値を獲得し、レベルアップ時にHP+20/射程+1/移動距離+1/弾数+1から1つ選んで強化
- ステージを進めるごとに敵の数が増加し、配色・フォグ・床・境界装飾が5種類のテーマでループして変化(アセット不使用、全てコードで生成)
- 攻撃ヒット・撃破・被弾・レベルアップ・ステージクリア/敗北の各タイミングで効果音が鳴る(音声ファイル不使用、サイン波合成でコードから生成)
- 勝敗判定、Rキーでリトライ、Spaceキーで次ステージへ進行

## アーキテクチャ

| スクリプト | 責務 |
|---|---|
| `GameManager` | ターン管理・勝敗判定・結果画面・ステージ遷移を統括するシングルトン |
| `EnemyAI` | 敵1体分の移動・攻撃判定(近接/遠距離タイプの分岐、重なり・障害物回避を含む) |
| `EnemyKind` | 敵1体ごとの種別(近接/遠距離)と遠距離時の希望距離を持つだけのデータ用コンポーネント |
| `ClickToWorldPosition` | プレイヤー入力(クリック→移動/攻撃の判定) |
| `PlayerHealth` / `EnemyHealth` | HP管理・ダメージ処理・撃破時の経験値/勝敗連携 |
| `PlayerProgress` | レベル・経験値・強化内容を保持する静的クラス(シーン再読み込みを跨いで保持) |
| `AttackFX` | 近接/遠距離の攻撃演出(コルーチン+コールバックで演出とダメージ計算を分離) |
| `AudioFX` | 効果音(ヒット・撃破・被弾・レベルアップ・クリア・敗北)をサイン波合成でその場生成する静的クラス(音声アセット不使用) |
| `EnemySpawner` / `PlayerSpawner` | 開始時のユニット配置(障害物マスを避けて配置) |
| `GridObstacles` / `GridObstacleView` | ステージ番号から障害物マスを決定論的に算出する判定ロジックと、その見た目の配置 |
| `ScenePolish` | 背景色・フォグ・チェッカーボード床・簡易地形装飾をコードから自動生成 |
| `PlayerProgressUI` / `LevelUpChoiceUI` / `HealthBarController` / `DamagePopup` / `TitlePanel` | UI表示系(いずれもプレハブ不使用、コードで生成) |

## 自分で判断した設計ポイント(抜粋)

- **敵AIの責務分離**: 元々は`GameManager`に移動・攻撃ロジックを直接書いていたが、ターン管理・勝敗判定・UI生成まで1クラスに集中していたため、敵の行動だけ`EnemyAI`に切り出した。
- **`PlayerProgress`を静的クラス化**: ステージ遷移(`SceneManager.LoadScene`によるシーン再読み込み)を跨いでもレベル・強化内容が消えないようにするため。
- **演出とダメージ計算の分離**: `AttackFX`は「演出が終わったらコールバックを呼ぶ」だけの役割にして、実際のダメージ計算・UI更新は呼び出し元に残した。
- **アセット無しでの画面づくり**: `ScenePolish`で床・フォグ・装飾をコードから生成し、3Dモデルや画像アセットが無くても殺風景にならないようにした。
- **防御的な初期化**: 各コンポーネントに「無ければ自動で付ける」処理を入れ、インスペクタ設定漏れによるNullReferenceExceptionが起きにくい構成にした。
- **障害物判定を純粋関数にした**: `GridObstacles.GetBlockedCells(stage, width, height)`はステージ番号だけから結果が決まる静的関数にしている。障害物を参照するスクリプトが6個(`EnemyAI`・`ClickToWorldPosition`・`AttackRangeShower`・`EnemySpawner`・`PlayerSpawner`・`GridObstacleView`)あり、Unityの`Start()`実行順はオブジェクト間で保証されないため、どこかの状態を共有して持つより「いつ呼んでも同じ結果を返す関数」にする方が安全だと判断した。
- **敵バリエーションの比率・障害物の数はまだ仮の固定値**: 遠距離タイプの出現比率(ステージ2以降、3体に1体)、障害物の数(3+ステージ数、最大6個)と配置(外周を避けて内側のマスのみ)は、プレイ感を見ながら調整する前の初期値。数値は`EnemySpawner.SetupEnemyKind`と`GridObstacles.GetBlockedCells`に直接書いてあるので、触ればすぐ調整できる。

## 既知の制限・今後の改善点(正直ベース)

- 敵AIは1ターンに1体だけ行動する。近接タイプは追跡のみ、遠距離タイプも「近すぎたら離れる・遠すぎたら詰める・射程内なら攻撃」という固定パターンのみで、複数の敵が連携するような動きはない。ステージが進んでも敵自体の基礎HP・攻撃力は変わらず、種類と数だけ増える。
- 障害物マスは移動を塞ぐだけで、遠距離攻撃の射線を遮る判定はない(壁の向こうにいる敵・プレイヤーにも遠距離攻撃は届いてしまう)。
- `GameObject.FindGameObjectsWithTag("Enemy")`を複数箇所(`EnemyAI`・`ClickToWorldPosition`)で毎ターン呼んでおり、敵数が大きく増える場合はリストをキャッシュする設計に変える必要がある。
- 自動テストは未整備。
- ステージテーマ(5種)・障害物配置はループ/ランダム生成のみで、ボスや固有イベント、手作りの見せ場は無い。

## 動作環境

- Unity(Universal Render Pipelineを想定。シェーダー取得時にStandardへのフォールバックあり)
- 敵オブジェクトに"Enemy"タグが必要
